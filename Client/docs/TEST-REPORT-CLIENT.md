## 4. 环境阻塞项与整改结果

> **2026-11-14 复测结论**：4.1 与 4.2 两项已由服务端整改完毕。`putUrl` 现为
> `http://192.168.10.4:9000/...`，PUT 返回 `200`、`:complete` 返回 `READY`、
> `createFromPages` 返回 `201` 且任务到达 `SUCCEEDED`；`shareLink` 返回
> `http://192.168.10.4:8080/s/{token}`，公开 JSON 与 HTML 页均 `200`。
> 因此本轮接口断言从 66/72 提升到 77/77。

### 4.1 预签名地址指向容器内网名（阻塞取图、转换、导入三条链路）

**现象**：`POST /v1/uploads` 返回的 `putUrl` 形如
`http://minio:9000/gleannote-private/u/...?X-Amz-Signature=...`，客户端 PUT 时报
`502 upstream connect failed: 不知道这样的主机 (os error 11001)`，随后 `:complete` 返回
`409 UPLOAD_SIZE_MISMATCH`，`notes:createFromPages` 返回 `409 UPLOAD_NOT_READY`。

**根因**：服务端 `GN_S3_ENDPOINT` 取值为 `http://minio:9000`（compose 内网服务名），
且 MinIO 端口映射为 `127.0.0.1:9000`，只监听回环，局域网客户端无法访问。

**影响**：6 项接口断言、4 个界面（SCR-03/04/05/06）与 SCR-08、SCR-14、SCR-15 无法验证。

**整改建议**（已同步到 `Server/compose.yaml` 与 `Server/.env.example`，需重新部署）：

```bash
# .env
GN_BIND_ADDR=0.0.0.0
GN_S3_ENDPOINT=http://192.168.10.4:9000
GN_PUBLIC_BASE_URL=http://192.168.10.4:8080
```

改完后 `docker compose up -d` 重启，`putUrl` 主机将与客户端可达主机一致，本节用例可直接重跑。

### 4.2 分享链接前缀为回环地址

**现象**：`POST /v1/notes/{id}/shareLink` 返回 `http://127.0.0.1:8080/s/{token}`，
在手机或其它设备上打不开。

**根因**：`GN_PUBLIC_BASE_URL` 为默认值 `http://127.0.0.1:8080`。

**已排除**：token 本身有效。改用 LAN 地址访问同一 token，`GET /v1/public/shares/{token}` 返回
`200`，`GET /s/{token}` 返回 `200 text/html` 且标题与样式正常。因此这是配置问题，不是客户端或分享功能缺陷。

## 5. 已修复缺陷

| 编号 | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| D-01 | 启动屏用 `collectAsState(initial = false)` 判断登录态 | 已登录用户冷启动被踢回登录页 | 改为 `initial = null`，拿到 DataStore 真实值后再跳转；深链判断同步改为 `loggedIn == true` |
| D-02 | 回收站恢复/彻底删除只调接口，不刷新本地表 | 恢复后条目仍留在回收站，直到重进页面 | 新增 `LocalStore.replaceTrash`（事务内先清空再写入）；恢复/彻底删除/删除后统一 `refreshAfterTrashChange` |
| D-03 | 令牌刷新单飞存在竞态 | 并发 401 可能触发多次刷新，导致令牌被服务端判定复用而全设备吊销 | 「检查 + 创建 + 登记」放入同一 `Mutex` 临界区；新增 3 并发用例断言刷新次数为 1 |
| D-04 | 注册页强制要求验证码非空 | 服务端已跳过校验时无法注册 | 按钮可用条件去掉 `code.isNotBlank()`，验证码交由服务端裁决；标签提示「开发环境可留空」 |
| D-05 | 进入目录时只刷新笔记、不刷新子目录 | 目录卡片上的「N 篇笔记」长期停在旧值（实测显示 0 篇但实际 1 篇） | `LibraryScreen` 在 `currentId` 变化时同时 `refreshFolders(currentId)` |
| D-06 | 本地目录表只 upsert、从不删除 | 删除目录后列表仍显示该目录（实测服务端已在回收站，界面仍可见） | 新增 `LocalStore.replaceFolders`（按父级裁剪后写入）与 `removeFolder`；`deleteFolder`/`expungeFolder` 成功后同步移除本地行 |
| D-07 | 未授予相机权限时，从相册选完图片后界面仍停在「相机未授权」说明页 | 权限分支里 `return@Column` 截断了后续内容，缩略图条与「下一步」都不渲染，用户以为相册不可用 | 权限页改为普通卡片不再提前返回；相册做成底部常驻入口，与拍照并列，不依赖相机权限 |

### 7.2.1 模拟器无法出 NAT 时的联调通道

本轮实测发现本机模拟器的 QEMU NAT 无法访问局域网（`ping 192.168.10.4` 与公网均 100% 丢包，仅 `10.0.2.x` 可达），
属于宿主环境问题而非应用问题。绕行方案（客户端代码零改动）：

```bash
# 1) 宿主机起转发：8081 -> 服务端 8080，9001 -> 服务端 9000（对象存储）
#    注意必须绑 127.0.0.1；绑 0.0.0.0 时该进程出站会被 Windows 防火墙拦截（实测 10061）
python Client/tools/e2e/port_forward.py --target 192.168.10.4

# 2) adb 反向通道（adbd 重启后需重做）
adb reverse tcp:8082 tcp:8081
adb reverse tcp:9002 tcp:9001

# 3) 模拟器内把预签名地址 DNAT 到反向通道（预签名 Host 头保持不变，签名仍有效）
adb root
adb shell "sysctl -w net.ipv4.conf.all.route_localnet=1"
adb shell "iptables -t nat -A OUTPUT -p tcp -d 192.168.10.4 --dport 9000 -j DNAT --to-destination 127.0.0.1:9002"

# 4) 用反向通道地址构建 APK
cd Client && gradle assembleDebug -PGN_BASE_URL=http://127.0.0.1:8082/v1
```

真机联调时无需以上步骤，直接把 `GN_BASE_URL` 设为 `http://192.168.10.4:8080/v1` 即可。
